# LingoPrep Backend

Backend for the AI English Practice & Assessment Platform for IELTS/Aptis Speaking & Writing.

This backend is designed as a complete MVP backend for the `Document.docx` requirement: authentication, RBAC, question bank, Speaking/Writing submissions, AI formative feedback, CEFR/Band results, progress dashboard, teacher review, admin monitoring, Redis/MinIO infrastructure, OpenAPI/Swagger, Docker, and automated tests.

## 1. Tech stack

- Python 3.11
- FastAPI
- SQLAlchemy 2.x
- Pydantic v2
- JWT Bearer auth with bcrypt password hashing
- PostgreSQL for Docker/production-like mode
- SQLite fallback for local demo when PostgreSQL is unavailable
- Redis for cache/queue-ready infrastructure and health check
- MinIO/S3-compatible object storage for Speaking audio artifacts
- Pytest for backend API/contract tests
- Swagger/OpenAPI generated by FastAPI
- Dockerfile + Docker Compose
- GitHub Actions CI in `.github/workflows/ci.yml`

## 2. Backend architecture

```text
React/Vite Frontend
  -> FastAPI REST API
    -> Auth/JWT + RBAC dependencies
    -> Routers
       - auth
       - questions
       - submissions
       - reviews
       - dashboard
       - chat
       - admin
       - ai_test
    -> Services
       - Redis cache/status
       - MinIO/S3 object storage
       - AI writing/speaking evaluators
       - STT/ASR/TTS helpers
    -> SQLAlchemy models
       - PostgreSQL in Docker
       - SQLite fallback locally
```

## 3. Database/schema design

Main tables:

| Table | Purpose |
| --- | --- |
| `users` | Learner/Teacher/Admin accounts, password hash, role, target score. |
| `questions` | IELTS/Aptis question bank: exam type, skill, part, prompt, timer, word limits, tags. |
| `submissions` | Learner Speaking/Writing attempts, text/transcript/audio path, status. |
| `assessments` | AI feedback result: band, CEFR, rubric scores, strengths, weaknesses, inline feedback, model answer, recommendations. |
| `teacher_reviews` | Teacher final review/override and notes. |
| `notifications` | In-app notifications for evaluation/review status. |
| `chat_sessions` | AI tutor session container. |
| `chat_messages` | AI tutor conversation messages. |
| `rubrics` | Versioned exam/skill rubric definitions and CEFR mappings. |
| `ai_profiles` | Configured AI providers/models/purposes. |
| `assessment_jobs` | Job metadata for assessment processing, status, attempts, error message. |
| `audit_logs` | Audit trail for admin/config/submission/review actions. |

SQL files:

- `db/init.sql` - PostgreSQL Docker init hook.
- `migrations/001_initial_schema.sql` - full initial PostgreSQL schema.

Runtime note: FastAPI currently calls SQLAlchemy `Base.metadata.create_all()` on startup for demo speed. For production, use migration tooling such as Alembic.

## 4. RBAC by role

| Feature/API group | Public | Learner | Teacher | Admin |
| --- | ---: | ---: | ---: | ---: |
| Register/Login | yes | yes | yes | yes |
| `GET /api/questions` | yes | yes | yes | yes |
| `POST/PUT/DELETE /api/questions` | no | no | no | yes |
| Submit Writing/Speaking | no | yes | yes* | yes* |
| `GET /api/submissions` | no | own list | own list | own list |
| `GET /api/submissions/{id}` | no | owner only | all | all |
| Request teacher review | no | owner only | owner only | owner only |
| Teacher review queue | no | no | yes | yes |
| Submit teacher review | no | no | yes | yes |
| Learner dashboard | no | yes | yes* | yes* |
| Chat sessions | no | own sessions | own sessions | own sessions |
| Admin stats/users/rubrics/AI profiles/jobs/audit/infra | no | no | no | yes |
| AI Studio debug `/api/ai/*` | mostly public debug endpoints | yes | yes | yes |

`*` Current dependency allows authenticated users on some learner endpoints if they own or create their own resource. Admin/Teacher broad access is explicitly implemented for submission detail and review endpoints. For stricter production separation, add dedicated `require_learner` to learner-only submission endpoints.

## 5. Business workflow

### Learner Writing

1. Learner logs in and receives JWT.
2. Learner gets a Writing question from question bank.
3. Learner submits essay to `POST /api/submissions/writing`.
4. Backend creates `submissions` and `assessment_jobs` records.
5. Writing evaluator returns structured feedback.
6. Backend stores `assessments`, updates job status, creates notification and audit log.
7. Learner views result and dashboard.
8. Learner can request teacher review.

### Learner Speaking

1. Learner gets a Speaking prompt.
2. Learner submits transcript and optionally audio to `POST /api/submissions/speaking`.
3. Audio is saved in `uploads` and mirrored to MinIO if available.
4. STT/transcript handling + speaking evaluator produce structured result.
5. Backend stores assessment, job status, notification, audit log.

### Teacher Review

1. Teacher logs in.
2. Teacher opens `GET /api/reviews/queue`.
3. Teacher posts final review to `POST /api/reviews/{submission_id}`.
4. Backend stores/updates `teacher_reviews`, marks submission `REVIEWED`, notifies learner.

### Admin Management

Admin can:

- View stats, users, jobs, audit logs, infra status.
- Update user role.
- CRUD question bank.
- CRUD rubrics.
- CRUD AI profiles.

## 10. Current known limitations

- Some AI endpoints are intentionally local-first/fallback-friendly for demo stability.
- Redis is wired and visible for health/queue-ready infrastructure; assessment processing is still synchronous in the API request path.
- MinIO is used as best-effort mirror for uploaded Speaking audio; local upload fallback remains active.
- Pydantic `class Config` warnings are non-blocking; refactor to `ConfigDict` is recommended for warning-free output.
- For production, replace `create_all()` startup schema creation with Alembic migrations and strict environment secret management.
